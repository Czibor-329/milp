# 调度性能口径与两类控制假设验证

## 1. 为什么不能只看 ProcessMove

Cluster Tool 的周期下界同时受工艺步骤负载和机器人负载约束。并行腔室
增加后，瓶颈可能从工艺腔转移到 VTR、ATR 或 LoadLock，因此仅累加
ProcessMove 会高估可用产能，也无法解释“腔室空闲但系统仍不出片”。

前端按物理资源合并以下区间，重叠时间只计算一次：

- 工艺腔：加工、清洁、该腔室上的开关门和 Pick/Place/Swap；
- LoadLock：抽气、充气、开关门和 Pick/Place/Swap；
- 机器人：PreTrans、Pick、Place 和 Swap；
- LoadPort：开关门和 Pick/Place。

机器人在站点间的移动只计入机器人，不重复计入两端腔室。分析结果内部仍保留
设备定义中的全部工艺腔和 LoadLock，但主界面只显示当前统计窗口内有物理占用
的资源，避免大量 0% 行掩盖有效信息。

## 2. 统计窗口与瓶颈识别

默认窗口从“首片返回 LoadPort”开始，到“末片离开 LoadPort”结束，
用来剔除启动填充和末批排空。若样本过少或两者不相交，则退化为中间
80% 的近似窗口，并在界面上标明。用户也可以切换到完整周期。

每个资源输出：

- 物理占用率：合并后的忙碌时长 / 统计窗口；
- 平均连续忙碌：所有 Active Period 的平均长度；
- 最长空闲：统计窗口内相邻忙碌区间的最大间隔；
- 占用组成：加工、清洁、开关门、取放/搬运、抽充气和其他。

瓶颈识别先建立三类可比的容量候选：

- 工序容量组：同一道工序可用的 PM1/PM2 等并行腔作为一个整体，容量利用率为
  组内物理忙碌总时长 /（并行腔数量 × 统计窗口）；
- 机器人：VTR、ATR 等分别作为传输容量候选；
- LoadLock 容量组：实际参与生产的 LoadLock 按总忙碌容量统计。

候选排序以容量利用率为主，最长空闲折算的连续性和同类相对强度为辅。得分接近
的候选会同时保留并显示证据强度，不再强行输出唯一瓶颈。平均连续忙碌仍展示在
资源表中，但不再跨 PM、Robot、LoadLock 直接比较；因为 ProcessMove 的自然
持续时间远长于机器人原子动作，直接比较会系统性误判低占用 PM。

这个结果仍是静态诊断候选，不是论文中逐时刻计算 sole/shifting bottleneck
概率的完整 APM，也不声称“改善首位候选一定等比例提高吞吐”。

### 指标有效性与边界

| 指标 | 是否保留 | 可以回答 | 不能单独回答 |
| --- | --- | --- | --- |
| 资源物理占用率及组成 | 保留，核心指标 | 加工、门、搬运、抽充气分别消耗了多少产能 | 哪个资源一定是系统瓶颈 |
| 平均活跃期 | 保留，辅助证据 | 同一类资源中谁持续处于非等待状态 | 跨 PM/Robot/LoadLock 直接排名，或单独证明瓶颈 |
| 最长空闲 | 保留，辅助诊断 | 暴露 PM 饥饿、机器人/LoadLock 服务断层和未充分供料 | 空闲由上游、下游、配方还是策略中的哪一项造成 |
| 稳态吞吐与平均出站间隔 | 保留，结果指标 | 在排除启动/收尾后系统实际产出速度 | 排程中的局部拥堵位置 |
| 出站间隔 CV | 保留，描述性指标 | 出片是否均匀、是否成团 | 波动的根因；CV 高并不自动意味着 makespan 更差 |
| 队列交织度和最长连续 Job | 保留，描述性指标 | 顶层是否形成长串同 Job 或频繁交织 | 交织是否最优；该值不是越高越好 |
| 入队时目标腔忙闲、至加工等待 | 保留，关键解释指标 | 真空端发片是否过早、是否把晶圆送向尚未就绪的加工能力 | 完整的因果瓶颈证明 |
| 加工腔晶圆驻留时间 | 保留，质量与调度指标 | 加工完成后晶圆因门、机器人或下游阻塞滞留多久 | 仅凭时长不能区分具体阻塞根因 |
| 机器手持片非运输驻留 | 保留，等待指标 | 晶圆已在机器人上、但机器人没有执行显式运输的等待多久 | MoveList 未显式记录的内部移动无法被扣除 |
| 晶圆系统停留时间及 CV | 保留，流动与稳定性指标 | 单片从离开 LP 到返回 LP 的周转水平和离散程度 | CV 不能替代吞吐、出站间隔或逐片时序检查 |

### 三类新增时间指标的事件口径

- **加工腔晶圆驻留时间**：`ProcessMove.EndTime` 至同一晶圆从同一加工腔
  Pick/Swap 完成的时间。以“完全离腔”为终点，因此包含开门、等待机器人和取片
  动作期间仍实际位于腔内的时间。每次加工访问单独形成一个样本，支持重复进腔。
- **机器手持片非运输驻留**：晶圆 Pick 完成（或 Swap 从腔室取片完成）至
  Place 开始（或 Swap 向腔室放片开始），再扣除区间内同一机器人的显式
  `PreTransMove` 时间。该指标刻画持片等待，不把取放动作和可识别的运输时间
  混入；若上游 MoveList 把运输隐藏在动作间隙中，结果会保守地将其计为等待。
- **晶圆系统停留时间**：晶圆从 LoadPort Pick 完成至返回 LoadPort Place
  完成。除均值、中位数和最大值外，同时报告逐片系统停留时间的变异系数
  `CV = 标准差 / 均值`，用于观察周转时间是否稳定。它与“相邻完工片的出站间隔
  CV”含义不同：前者衡量单片经历，后者衡量产出节拍，两者并列保留。

三类样本都按结束事件归属当前统计窗口：加工腔驻留以离腔时刻、机器手驻留以
开始放片时刻、系统停留以返回 LP 时刻判断。这样稳态窗口中的吞吐、出站节拍和
驻留统计使用相同的完工归属原则，同时允许样本的起点位于窗口之前。

文献支持这种“结果指标 + 变异指标 + 状态分解”组合，而不支持只靠单一利用率
排名。Jacobs 等人在半导体制造中指出，OEE/均值型指标不包含变异，而有效加工
时间的均值与变异需要共同解释周期时间；Chen 等人的晶圆厂排队网络实证也指出，
拥堵和延迟与运行环境的变异直接相关。因此界面保留 CV，但明确把它标成描述性
指标。Active Period 研究支持用机器状态识别候选瓶颈并覆盖并行系统，但其
“active”不是任意物理动作时长的简单拼接。因此本模块把 APM 限定为辅助启发，
跨类型排序回到容量利用率，并同时展示加工、清洁、门、搬运和抽充气组成。

## 3. 真空端入队序列假设

前端把晶圆第一次从 LoadLock 交给 VTR 的顺序定义为“真空端入队序列”，
并显示：

- 晶圆、PJob、LoadLock 和首个目标 PM；
- 入队时目标 PM 是忙还是闲；
- 入队到首次加工的等待时间；
- 相邻晶圆的 Job 切换率和最长同 Job 连续片数。

这不是把算法简化成一个固定 FIFO。它是顶层派工需要显式优化的队列，
同时仍受门、压力、机器人、驻留时间和 PM 可行性约束。

### 现有测试集结果

下表是同一输入上重新运行的首次排程 makespan，单位为秒。`UCB-2` 是当前
默认精评预算，`UCB-全组合` 用于验证启发式配置空间是否包含明显更好的
结构。

| 测试 | Heuristic | UCB-2 | UCB-全组合 | 相对 Heuristic |
| --- | ---: | ---: | ---: | ---: |
| 同构 t1 | 679.09 | 665.43 | 609.00 | -10.3% |
| 同构 t2 | 970.66 | 909.54 | 718.36 | -26.0% |
| 同构 t3 | 701.23 | 701.23 | 701.23 | 0.0% |
| 同构 t4 | 810.58 | 740.46 | 680.87 | -16.0% |
| 异构/共用 PM3 t1 | 1829.61 | 1656.08 | 1411.70 | -22.8% |
| 异构/共用 PM3 t2 | 1134.98 | 969.15 | 917.28 | -19.2% |

直接遍历配置后，`balanced-flow` 与 `no-exchange-throughput` 两个结构探针
覆盖了这六个实例中的全部最优配置。典型的真空端 Job 序列也从
`111222111222` 或较长同 Job 连续段，变为更接近
`121212...` 的交错序列；同构 t2 的 PM1/PM2 稳态占用率同时达到 100%，
而不是一个满载、另一个长期空闲。

因此，这个直觉得到当前测试集支持，但更准确的表述是：

1. 优化变量应包含真空端释放顺序，而不是只在动作已经可行后选择机器人动作；
2. 释放决策必须联合目标 PM 的最早可用时间、VTR 预计可用时间和
   LoadLock 周期；
3. “强制交替 Job”不是通用规则。正确目标是减少后续阻塞和饥饿，交替只是
   两个同构 Job 上常见的结果。

现有 Machine 快照已经提供站点 `ready_at`，候选动作也有
`earliest_start`、`finish_time` / `projected_ready_time`。因此当前主要问题
不是算法完全看不到腔室忙闲，而是 legacy 优先级和 UCB-2 候选预算没有稳定
选中能利用这些状态的配置。短期可把上述两个结构探针设为多 Job 场景的必评
候选；长期应把队头 PJob、目标 PM 最早可用时间、VTR 等待和连续同 Job
长度加入学习特征。

## 4. 固定节拍假设

实验在 LoadPort 发片动作上增加了“不得早于”的固定间隔，并用并行 PM
理论加工能力推导间隔，再测试 0.25、0.5、0.75、1.0 和 1.25 倍。

现有测试集没有出现 makespan 改善：

- 间隔短于系统自然发片间隔时，约束没有生效，排程不变；
- 间隔开始约束系统时，只会注入额外空闲；
- 在同构 t3 上，1.0 倍使 makespan 恶化约 2.8%，1.25 倍恶化约 26.6%。

原因是当前 Machine 已由 ATR、门、LoadLock 压力切换和槽位互锁自然串行化
发片。固定“四等分”没有看到 VTR 是否即将被出片任务占用，也没有看到各 PM
实际完工相位，所以不能作为默认控制律。

更合适的后续方向是软节拍：当预测到多个 PM 在一个机器人服务窗口内同时
完工时，对过早入片增加惩罚；只有在“减少的 VTR 峰值等待”大于“新增 PM
空闲”时才错峰。前端新增的入队等待、目标 PM 忙闲、出站间隔 CV、机器人
Active Period 和最长空闲可以直接用于这类触发条件与 A/B 验证。

## 5. 测试组评估口径

测试组分析不把 makespan、计算时间和设备利用率加权成一个综合分数，因为这些
指标量纲不同，任意权重会隐藏实际取舍。组级页面按四类分别报告：

| 维度 | 组级指标 | 逐测试信息 |
| --- | --- | --- |
| 有效性 | 成功数、MoveList 校验通过率 | 失败原因、校验状态 |
| 排程质量 | 总 makespan 加权改善、逐例中位改善、胜/平/退化数、最差退化 | makespan、Baseline、相对改善和 performance ratio |
| 计算成本 | CPU Time 中位数、P90、总计 | 每例 CPU Time |
| 设备与流动 | 首位瓶颈利用率中位数、容量组频次、吞吐和出站 CV 中位数 | 每例多个瓶颈候选、可能性、利用率、吞吐、CV、统计窗口方法 |

总 makespan 改善按各测试 Baseline makespan 加权，便于衡量测试组整体节省；
中位改善和胜/平/退化数则防止少数长用例掩盖多数短用例的退化。逐例图和完整表
始终保留，不只显示汇总数。这与 Dolan–Moré performance profile 的核心原则
一致：算法比较应基于逐问题相对表现分布，而不是只用一个总平均。

SEMI E10/E79 把设备状态、利用率、生产率和吞吐区分为不同度量。因此页面将
“物理占用率”明确限定为 MoveList 统计窗口内的活动时间并集，不把它标成完整
OEE；吞吐、波动和校验另行展示。计算时间使用中位数与 P90，同时保留逐例值，
以暴露搜索预算是否带来长尾延迟。

实现边界也已拆分：

- `realtime_scheduler/analysis/movelist_performance.ts`：无 DOM 的 MoveList
  占用、Active Period、吞吐、波动与队列计算；
- `realtime_scheduler/analysis/group_performance.ts`：无 DOM 的测试组聚合；
- `realtime_scheduler/analysis/schedule_context.ts`：无 DOM 的 Route/PJob
  并行工序容量组提取；
- `alg/src/validation`：MoveList 状态和物理合法性的唯一 Python 校验实现；
- 前端只负责加载结果和绘图，不复制上述业务规则。

## 6. 文献依据

- Kim 与 Lee 的 Cluster Tool 周期调度研究同时计算工艺步骤和机器人工作量，
  并用两者最大值作为周期下界：
  <https://doi.org/10.3182/20130619-3-RU-3018.00108>
- Roser 等人的 Active Period Method 以最长不间断活动时间识别瞬时和迁移
  瓶颈：
  <https://doi.org/10.1007/978-3-030-85874-2_74>
- Yang 等人的双晶圆类型研究明确联合优化晶圆类型释放顺序和机器人任务顺序：
  <https://doi.org/10.1016/j.eswa.2025.128209>
- Qiao 等人把启动瞬态与稳态周期分开建模，支持在分析中剔除启动/收尾：
  <https://doi.org/10.1109/TCST.2016.2598762>
- Lee 的 Cluster Tool 调度综述把晶圆驻留定义为加工结束后到机器人卸片
  的腔内等待，并指出该等待应减少、消除或保持稳定以保护表面质量：
  <https://www.informs-sim.org/wsc08papers/263.pdf>
- Qiao、Wu 与 Zhou 对活动时间波动下的单臂 Cluster Tool 建模，将 wafer
  sojourn time 明确限定为晶圆在加工模块内的停留，并分析其延迟上界：
  <https://web.njit.edu/~zhou/qiao-wu-zhou2011.pdf>
- Liu 等人把机器人周期拆成已知的搬运任务时间与由排程决定的机器人等待时间，
  支持机器手驻留指标中分离显式运输和等待：
  <https://doi.org/10.1177/1687814016646503>
- Gupta、Sivakumar 与 Lendermann 用仿真分析 Cluster Tool 的整体 cycle time，
  其系统边界包含晶圆经 LoadLock 进入、加工并退出设备：
  <https://doi.org/10.1504/IJMTM.2011.045508>
- Romauch 与 Hartl 指出 LoadLock 是进入真空主腔的入口，也是重要潜在瓶颈：
  <https://doi.org/10.1016/j.ijpe.2017.01.005>
- Subramaniyan 等人的实时 Average Active Period 方法以“机器不在等待的平均
  连续时长”检测瓶颈，并覆盖并行系统：
  <https://research.chalmers.se/publication/244931>
- Jacobs 等人指出半导体常用 OEE 只包含均值、不包含变异，并用有效加工时间的
  均值与变异共同解释周期时间：
  <https://doi.org/10.1109/TSM.2003.815215>
- Chen 等人的晶圆厂排队网络实证表明，运行变异是拥堵和等待的重要来源：
  <https://doi.org/10.1287/opre.36.2.202>
- Robinson 的稳态仿真研究说明初始瞬态会造成估计偏差，支持删除 warm-up 数据；
  当前“首片完工—末片投料”是面向有限批次的透明启发式窗口，并不冒充统计检验：
  <https://doi.org/10.1016/j.ejor.2005.08.048>
- SEMI E10 提供设备可靠性、可用性、可维护性与利用率的统一状态度量，并覆盖
  多路径 cluster tool 的模块级信息：
  <https://store-us.semi.org/products/e01000-semi-e10-specification-for-definition-and-measurement-of-equipment-reliability-availability-and-maintainability-ram-and-utilization>
- SEMI 官方 E10/E79 指标概览将利用率与生产率、OEE、吞吐区分开，支持本页面
  分维度展示而非合成单分：
  <https://www.semi.org/en/products-services/standards/step/equipment-performance-metrics>
- Dolan 与 Moré 的 performance profile 用逐问题性能比的累积分布比较求解器，
  支持保留逐例对比和胜/平/退化，而非只报告总体平均：
  <https://arxiv.org/abs/cs/0102001>
- Optimization Benchmarking Survey 强调基准目标、问题集、性能度量、
  可复现性和完整报告应共同设计：
  <https://arxiv.org/abs/2007.03488>
